# 协议核心

核心使用独立 TypeScript 实现，不依赖 Vue、界面控件或 Tauri。

## 已实现：Modbus CRC16

模块：`checksum/crc16.ts`。输入支持只读数值数组和 `Uint8Array`；普通数组的每个元素必须为 0～255 的整数，非法输入抛出中文 `RangeError`。函数不修改输入。

- `calculateCrc16(data)`：返回 16 位 CRC 数值；空输入返回初始值 `0xFFFF`。
- `formatCrc16Bytes(crc, order)`：位于 `checksum/crc16-format.ts`，仅格式化 CRC 数值为字节；默认 `low-first`，可选 `high-first`。
- `verifyCrc16(frame, order)`：按指定字节顺序把末尾两个字节作为 CRC，默认 `low-first`，可选 `high-first`；返回 `valid`、`receivedCrc`、`calculatedCrc`，不足两个字节时报错。

示例：`01 03 00 00 00 02` 得到 `0x0BC4`，追加字节为 `C4 0B`。

完整输入的校验仅判断 CRC 是否匹配，不验证 RTU 地址、功能码、业务数据或帧长度规范。只有 `FF FF` 的输入按空数据 CRC 判断匹配，但不代表有效 RTU 报文。

算法采用初始值 `0xFFFF`、反射多项式 `0xA001`，不做最终异或，实际发送低字节在前。规范参考 [Modbus 串行规范 V1.02](https://www.modbus.org/docs/Modbus_over_serial_line_V1_02.pdf)，标准检查向量参考 [CRC RevEng](https://reveng.sourceforge.io/crc-catalogue/16.htm#crc.cat.crc-16-modbus)。

CRC16 已接入校验计算页面，支持计算、完整报文 CRC 校验、输出字节排序以及 CRC 字节和完整报文复制。校验按所选输出字节顺序提取 CRC，字节顺序不匹配时校验失败；切换顺序后已有校验结果自动更新。Modbus RTU 组帧必须固定低字节在前，不提供排序切换。

## 已实现：Modbus LRC

模块：`checksum/lrc.ts`。与 CRC16 共用字节输入校验，接受只读数值数组和 `Uint8Array`，不修改输入。

- `calculateLrc(data)`：累加数据字节，取低 8 位的二进制补码，返回 0～255；空输入返回 `0x00`。
- `verifyLrc(frame)`：读取末尾一个字节作为 LRC，返回 `valid`、`receivedLrc`、`calculatedLrc`；空报文抛出中文 `RangeError`。
- `formatLrcAsciiFrame(frame)`：将包含 LRC 的字节序列转为冒号开头、连续大写 HEX、实际 CRLF 结尾的 ASCII 文本；不添加空格，不重新计算 LRC，不验证业务结构。

计算针对 ASCII 编码前的原始数据字节，不包含帧起始冒号和结束 CRLF，不对 HEX 字符的 ASCII 码求和。校验仅判断 LRC 是否匹配，不验证 ASCII 帧结构；只有 `00` 的输入可以匹配空数据，但不是有效 Modbus ASCII 帧。

标准向量：`02 01 00 00 00 08` → `F5`，来自[三菱 MODBUS 接口模块手册表 4.6、4.7](https://dl.mitsubishielectric.com/dl/fa/document/manual/plc/sh080578eng/sh080578engk.pdf#page=68)。页面默认示例：`01 03 00 00 00 02` → `FA`。

校验计算页面为通用工具，目前提供 CRC16 / Modbus 和 LRC / Modbus ASCII。两种算法均支持计算、校验、复制校验字节和追加或替换校验值后的报文；LRC 为单字节，不显示字节顺序选项。空输入时填入对应算法的示例再执行，切换算法后清除旧结果并保留输入。LRC 校验输入仍使用 HEX 数据字节；完整报文输出以 `<CR><LF>` 显示结束符，复制包含 ASCII 帧的冒号和实际 CRLF，无空格，可按文本 / ASCII 模式发送。例如默认示例输出 `:010300000002FA` 后跟 CRLF。

## 已实现：数据类型转换

模块：`data-conversion.ts`。核心不依赖界面，供数据转换、后续报文生成和解析复用。

- `encodeDataValue(input, type, order?)`：十进制字符串编码为字节数组；整数先用 BigInt 校验范围，64 位整数编码不经过 Number。
- `decodeDataValue(data, type, order?)`：解码恰好一个数据项，64 位整数返回 bigint，其他类型返回 number；不修改输入。
- `getByteLength(type)` / `getByteOrders(type)`：获取类型长度和支持的字节序，默认采用首个标准大端顺序。
- `formatDataValue(value)`：格式化数值，保留负零和完整 64 位整数。
- `bytesToRegisters(data)`：按实际字节排列每两个字节拆分为一个 UINT16 寄存器，不额外交换顺序。

类型支持 UINT16、INT16、UINT32、INT32、UINT64、INT64、FLOAT32 和 FLOAT64。16 位字节序为 AB / BA；32 位为 ABCD / BADC / CDAB / DCBA；64 位为 ABCDEFGH / BADCFEHG / GHEFCDAB / HGFEDCBA。字母按标准大端字节依次编号，分别表示大端、寄存器内字节交换、寄存器顺序反转和全字节反转。FLOAT32 占 4 字节、两个寄存器，FLOAT64 占 8 字节、四个寄存器。

整数只接受十进制整数，不接受小数、科学计数法或进制前缀。浮点数接受小数、科学计数法、NaN 和正负 Infinity；有限数值溢出或下溢为零时报错，允许非零次正规数。浮点数按 IEEE 754 精度舍入，FLOAT32 舍入改变数值时页面显示提示。HEX 解码保留原输入字节，包括 NaN 的不同编码；重新编码 NaN 不保证保留原始 NaN 位模式。测试采用二进制补码整数向量，以及 [Oracle IEEE 格式说明表 3、表 5](https://docs.oracle.com/cd/E60778_01/html/E60763/z4000ac019878.html) 的浮点标准向量。

页面支持单项数值与 HEX 双向转换，空输入时按当前配置填入示例再转换；修改输入或配置后清除结果。提供数值和带空格 HEX 的复制，不提供系数和偏移量。

## 已实现：Modbus RTU 报文生成

模块：`modbus/builder.ts`，不依赖 Vue 或 Tauri。

- `buildRtuFrame(input)`：接受按报文类型、功能码区分的参数，校验后返回完整 `bytes`、不含从站地址和 CRC 的 `pdu`、字段名称 / 偏移 / 字节 / 说明，以及适用时的数量 `quantity`。
- `encodeRegisterItems(items)`：复用数据转换核心编码类型化数据项，返回字节、各项字节及寄存器总数；输入错误包含数据项序号。
- `packCoilStates(states)`：布尔状态按最低位在前打包，末字节未使用位补零。

支持 01、02、03、04、05、06、0F、10（十六进制）功能码的请求、正常响应及异常响应。读取状态数量为 1～2000，读取寄存器数量为 1～125，写多个线圈为 1～1968，写多个寄存器为 1～123。地址为 0～65535，同时检查末尾地址不越界。普通从站地址为 1～247，地址 0 仅允许写请求。CRC 固定低字节在前，地址和数量固定高字节在前；类型化数据区可选择设备需要的字节序。

10 请求与 03 / 04 响应的数据项允许混合类型，数量由完整编码长度计算；响应不包含起始地址。05 / 06 正常响应回显地址和写入值，0F / 10 正常响应仅包含起始地址和数量。异常响应只包含原始功能码加 0x80 及异常码。组帧只校验离线参数，不判断实际设备是否存在该地址或支持该功能。

协议测试独立比对 [Modbus 应用协议 V1.1b3](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf) 的各功能码 PDU 示例，CRC 封装使用固定完整 RTU 向量，并覆盖数量上限、地址边界、广播限制、位补零、混合类型和非法参数。

TCP 组帧与解析尚未实现。

报文生成界面按从站地址、功能码、协议地址、数量的顺序配置。协议地址默认十进制，可切换为不带 0x 前缀的十六进制；有效地址在切换时转换文本并保持实际数值，非法地址需修正后再切换。数据项列表使用公共表头，每项一行，写请求的位置显示跟随地址进制，读取响应使用寄存器序号；窄屏通过表格横向滚动保留行结构。HEX 和实际编码值在生成结果的字段明细中查看。

列表自动计算的数量仅显示在列表统计与生成结果中，不提供重复的只读数量输入框。报文结构按“字段、HEX、含义”展示，寄存器数据项合并为数据区，另以明细表显示位置、类型、字节序、HEX 和实际数值；字节偏移通过字段或位置的悬停提示查看。

协议地址通过“十六进制”勾选框切换进制，十六进制输入支持空格分隔，例如 `10 01`。05 的线圈状态和 06 的寄存器值与协议地址并排显示；线圈状态列表使用公共表头，每项一行。

0F 请求帧通过线圈数量控制按钮个数（1～1968），01 / 02 正常响应帧使用相同界面设置线圈或离散输入数量（1～2000），共用数量、状态数组和网格渲染。每行固定 8 个，按钮显示从 0001 开始的十进制序号，点击切换开关状态。按钮宽度随容器调整，右侧按内容宽度显示 HEX 和 8 位二进制数据，表头与各行对齐，不设置横向滚动条。二进制从高位到低位排列，最后一行未使用位补零。增加数量保留已有状态并补充关闭状态，减少数量截掉末尾状态，修改起始地址保留状态。01 / 02 响应不设置起始地址。

## 已实现：Modbus RTU 报文解析

模块：`modbus/parser.ts`，独立于 Vue 和 Tauri。

- `parseRtuFrame(input, frameType?, rules?)`：输入连续或空白分隔的 HEX，默认自动识别。返回完整字节、地址、功能码、CRC 校验、候选类型、协议字段、数据明细、错误、警告和规则结果。非法 HEX 或不足四字节时抛出中文错误；结构错误以结果中的 `errors` 返回。
- `parseFrameRules(bytes, rules)`：规则使用完整帧从 0 开始的偏移，支持已有全部数据类型和字节序。单条失败独立报告；64 位整数由 bigint 格式化为字符串，避免精度丢失。

支持 01、02、03、04、05、06、0F、10 的请求、正常响应与异常响应。CRC 固定低字节在前，CRC 状态独立于协议结构错误；CRC 不匹配不阻止字段解析。手动类型不自动切换。自动模式将请求、响应结构分别校验；同时匹配时 `candidates` 保留两个类型，`payload` 暂按请求结构展示，同时输出方向不确定的警告。无匹配时只展示通用字段与原始数据，手动选择可查看具体结构错误。未知功能码仅展示通用字段及 CRC，不将未检查的详细结构标为符合。

读取响应不包含起始地址，寄存器按序号展示；状态结果每行固定显示 8 个，01 / 02 响应按所有返回位展示，不能仅从响应确定末尾填充位或实际请求数量。寄存器默认按大端 UINT16 解码，业务浮点数和其他字节序通过规则指定。未知异常码保留原值并提示，不推断设备业务含义。离线 HEX 不包含串口时间信息，不检查帧间静默时间。

页面保留输入、规则、结果三区。修改输入、报文类型或规则后立即清空解析结果及字节高亮；字段按钮高亮对应原始字节，点击原始字节高亮所在协议字段。支持 RTU / ASCII 格式切换，TCP 选项禁用并标记待实现。单条帧解析不提供连续多帧拆分、请求响应配对或规则持久化。

解析规则配置沿用报文生成的数据项表格样式：公共表头、每条规则一行，包含字段名称、位置、数据类型、字节序和操作；添加按钮位于列表标题右侧，窄屏横向滚动保留行结构。

测试使用官方应用协议的独立 PDU 示例，业务结构测试故意使用零 CRC，与固定完整 RTU CRC 向量分开验证；覆盖所有首期功能码、异常响应、歧义、长度和数量边界、广播、状态位补零及规则错误。界面布局、交互、主题和响应式显示由用户测试。

## 已实现：Modbus ASCII 与公共业务核心

- `modbus/builder.ts` 的 `buildSerialBody(input)`：生成经校验的从站地址和 PDU，不含校验字节。RTU 封装追加 CRC16，ASCII 封装追加 LRC；两个封装共用全部业务处理。
- `modbus/parser.ts` 的 `parseSerialBody(bytes, frameType?)`：解析不含校验的从站地址和 PDU，共用结构验证、类型识别、广播检查、字段偏移、寄存器及状态解码。各封装分别处理传输长度、校验和规则。
- `modbus/ascii.ts` 的 `buildAsciiFrame(input)`：返回与 RTU 相同的 `pdu`、`fields`、`quantity`，`bytes` 包含解码后的地址、PDU 和单字节 LRC；额外的 `text` 为冒号、大写连续 HEX 及实际 CRLF 组成的完整帧。
- `parseAsciiFrame(input, frameType?, rules?)`：只接受单条冒号开头的 ASCII 文本。禁止数据区空格、非 HEX、奇数字符和多帧；兼容小写 HEX。缺失 CRLF、仅 CR 或仅 LF 时保留解码结果，同时在 `errors` 报告结束符问题；不 trim 输入，不默默修复。最大 513 个字符（含冒号及实际 CRLF），解码后最多 255 字节。

解析结果共有 `checksum`（`algorithm`、`valid`、`received`、`calculated`）；RTU 保留兼容的 `crc`，ASCII 另有 `lrc`、原始 `text` 和 `ending`。校验是否匹配与完整帧结构是否符合分别显示。规则偏移以解码后的从站地址为 0，不计冒号及结束符，可读取校验字节。ASCII 原始文本中每个解码字节对应的字符偏移为 `1 + 2 * offset`，用于联动高亮。

生成界面显示 CRLF 的可见标识，复制时保留实际 CRLF。解析界面通过 `normalizeAsciiTextInput` 将文本框末尾单个 LF 恢复为 CRLF，解决粘贴时浏览器归一化的问题；不补齐缺失结束符，不清理多余换行。核心 `parseAsciiFrame` 仍严格检查 CRLF；“补齐 CRLF 并解析”由用户明确选择，替换末尾 CR / LF 为标准 CRLF 后解析。格式、参数、输入、类型或规则变化后清除旧结果。两种格式共用参数、规则表格、数据明细和每行 8 个的状态展示。

ASCII 测试独立使用官方 PDU 示例和固定 LRC 常量，包含三菱手册完整帧向量；回归全部 RTU 测试。覆盖全部首期功能码、异常响应、结束符、小写、非法文本、最大长度、规则偏移、CRC / LRC 分离及广播与方向歧义。尚不支持 TCP、批量拆帧、自定义 ASCII 结束符及通信时序验证。
